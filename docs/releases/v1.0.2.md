# Core v1.0.2: masking and encryption hardening

This patch repairs the core independently of the proposed OpenTelemetry Logs
adapter. It does not publish that adapter or introduce a context-aware logging API.

## Security contracts

- Masking reconciles typed and legacy representations, including bound, static,
  indexed and descriptor-key fields. A stale representation must not restore a
  value overwritten by the masking transform.
- Regex rules operate on the original input and combine overlapping matches
  without leaving an exposed suffix. Invalid updates preserve the active policy.
- Removing a named policy removes its registration, not other policies sharing
  the same pattern. Updating a name replaces that registration. Clones retain
  independent configuration; each Apply observes one immutable local snapshot.
- The masker no longer retains arbitrary input/result strings in a process-lifetime
  cache. Retained-memory tests exercise 126,000 distinct synthetic inputs.
- Encryption results own their storage. Reusable scratch belongs to one call
  and is cleared before reuse. Prefix reads/writes are synchronized.

These are scoped contracts, not a guarantee that regex detects all PII, that
arbitrary nested values are recursively sanitized, or that all process memory
can be erased. See [SECURITY.md](../SECURITY.md) for encryption threat-model limits.

## Allocation boundaries

Strict uninstrumented tests protect field-name masking and the selected
whole-value regex redactions at zero allocations. Partial redaction that creates
an independent string has a different budget. Small warmed Encrypt/Decrypt calls
have a one-allocation budget; cold pools and large values can require more.

The allocation CI job runs on Windows and Linux, Go 1.24.0 and stable, separately
from race/coverage instrumentation. Only allocation-specific tests use a !race
build constraint; output-retention and security tests remain race-instrumented.
The core's existing JSON hot-path allocation guards remain unchanged.

## Reproduction

```sh
go test ./... -count=1
go test ./core -run TestZeroAlloc -count=1
go test ./masking -run 'Test.*Alloc' -count=1
go test -race ./... -count=1
go test ./masking -run '^$' -bench 'BenchmarkFieldEncryptor|BenchmarkEncryptionWorkloads' -benchmem -count=5
```

Published performance artifacts identify their original source hashes and
measurement boundary. Earlier local measurements are not a substitute for CI
on the final release commit, independent review, or production workload testing.

### Retained evidence

- [Core regression matrix](evidence/v1.0.2/core-regression-matrix.csv): 136
  root/probe cases from the local named-policy before/after experiment,
  Windows/amd64, Go 1.27.1, Core Ultra 9 285HX, three 100 ms samples per side.
  It compares the already-repaired candidate before/after policy ownership,
  not v1.0.1 against this complete release. Latency is exploratory.
- [Named-policy negative control](evidence/v1.0.2/named-policy-negative-control.jsonl):
  the new tests fail against the saved pre-fix policy implementation.
- [Encryption measurements](evidence/v1.0.2/encryption/benchmark-results.md):
  original before/after and payload-size runs, with their raw samples retained.
  The original encryption baseline is commit b57278a437caeccea2858dfeffc3f258735b7a90.
- Retained encryption fuzz logs are historical execution evidence, not exhaustive
  coverage or counts of independent security properties.

## Consumer boundary

Consumers of the existing otelbridge submodule do not automatically receive
this patch: its real go.mod requirement must be updated after this core version
is published. A developer-only replace directive is not a distribution fix.
